# ADR 0002: Skill Dependency Architecture & Graph Resolution

- **Status**: Accepted
- **Date**: 2026-07-29
- **Authors**: Louis & Agent Skill Team
- **Technical Story**: Establishing frontmatter dependency declarations, topological graph resolution, lockfile caching (`skills.lock`), and CI validation for Agent Skills.

---

## Context & Problem Statement

As the `agent-skills` ecosystem grows, skills increasingly depend on or enhance each other (e.g. `self-annealer` requires `tdd`, `context-gatherer` enhances `graphify`). Without explicit dependency modeling:

1. **Implicit Breakdown**: Missing required skills lead to silent runtime failures or undefined behavior when an agent invokes a skill that relies on another.
2. **Execution Order Ambiguity**: Tooling and orchestrators cannot determine the correct loading sequence or topological execution order.
3. **Circular Dependencies**: Unchecked cross-references between skills can create infinite loops or deadlocks.
4. **I/O Bottlenecks**: Scanning and parsing frontmatter files across $N$ skills on every agent activation introduces unnecessary disk I/O overhead.

We need a lightweight, deterministic dependency management architecture that fits our zero-external-dependency philosophy (ADR 0001).

---

## Decision Drivers

- **Zero Third-Party Manifest Files**: Frontmatter in `SKILL.md` must remain the single source of truth for single-file discoverability.
- **Fail-Loud vs Graceful Degradation**: Clear distinction between mandatory hard dependencies (`requires`) and optional soft enhancements (`enhances`).
- **Performance**: $O(1)$ lookup for runtime presence checks without $O(N)$ frontmatter parsing on every skill activation.
- **Zero-Dependency Resolution**: Cycle detection and topological sorting must be implemented in Python 3 stdlib without external graph libraries.
- **Continuous Integration Gate**: CI must catch missing dependencies, circular edges, and uncommitted lockfile drift before PRs are merged.

---

## Considered Options

1. **Option 1: Frontmatter Declarations + Kahn's Algorithm + Tracked `skills.lock` Cache** _(Selected)_
2. **Option 2: Standalone `package.json` / `manifest.json` Manifest Files**
3. **Option 3: Full Semver Dependency Resolution Engine (npm/Cargo style)**

---

## Decision Outcome

**Selected Option 1: Frontmatter Declarations + Kahn's Algorithm + Tracked `skills.lock` Cache**

### Rationale:

1. **Two-Tier Declaration in `SKILL.md`**:
   - `requires`: Hard execution dependency. Missing target fails loud at install/validation time.
   - `enhances`: Soft capability enhancer. Missing target warns once and gracefully degrades via written fallback instructions.
   - `version`: Kept as an optional no-op stub (`version: 1.0.0`) in the parser schema to ensure future schema extensions do not break existing parsers.

2. **Kahn's Topological Sort Algorithm (`scripts/depgraph.py`)**:
   - Uses standard library `collections.deque` to compute topological execution order and detect circular dependency cycles in $O(V + E)$ time.

3. **Tracked Lockfile (`skills.lock`)**:
   - Acts as a **Graph Resolution Cache & $O(1)$ Lookup Artifact** generated by `scripts/depgraph.py`.
   - Stores resolved topological order, direct dependencies, and transitive dependencies (`transitive_requires`, `transitive_enhances`).
   - Committed to git so developer environments, agents, and CI pipelines operate on the exact same validated graph snapshot.

4. **Install-Time & CI Gate Automation**:
   - `scripts/install_global.py` validates the graph before symlinking skills.
   - GitHub Actions (`.github/workflows/lint.yml`) runs `python3 scripts/depgraph.py --verify` to block PRs on missing dependencies, circular edges, or out-of-sync lockfiles.

---

## Positive Consequences

- Direct dependencies and optional enhancements are explicitly declared inside `SKILL.md` frontmatter.
- Circular dependencies and missing mandatory skills are caught immediately in CI and at install time.
- Runtime agents achieve $O(1)$ graph lookups via `skills.lock`.
- Completely adheres to ADR 0001 (Python 3 stdlib only, zero PyPI packages).

---

## Negative Consequences & Mitigation

- **Git Lockfile Sync Drift**: Developers editing `SKILL.md` frontmatters must regenerate `skills.lock` via `python3 scripts/depgraph.py --generate-lock`.
- **Mitigation**: `scripts/install_global.py` auto-regenerates `skills.lock` if safe, and CI (`depgraph.py --verify`) fails loud with clear instructions when `skills.lock` is out of sync.
